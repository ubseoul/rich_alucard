# Frozen art integration

Branch `claude/frozen-art-integration` (from `claude/presentation-director`), extended for ART SHIP 008 on `claude/art-ship-008-integration`, for ART SHIP 009 on `claude/art-ship-009-integration` and for ART SHIP 010 on `claude/art-ship-010-integration`: see `ART_SHIP_008_INTEGRATION.md`, `ART_SHIP_009_INTEGRATION.md` and `ART_SHIP_010_INTEGRATION.md` for those passes and `HQ_DECISIONS.md` for open HQ calls. This connects the frozen ART SHIP 004–010 corpus to the runtime through the Presentation Director. Frozen pixels are never modified: runtime scaling, cropping and framing only. This document is spoiler-safe: it holds ids, statuses and metrics, and reviewer evidence stays in the git-ignored `work/presentation_census/REVIEWER_ONLY/`.

## Architecture (data-driven, one path per asset)

| Layer | File | Role |
|---|---|---|
| Canonical registry | `js/data/art_registry.js`, generated by `tools/art-registry.mjs` | Every ART SHIP 004–010 file by runtime id: environments and exact-origin layers, character anchors and approved states, creatures, props, vehicles, UI icons and handoff sheets (provenance only). Built from each Ship's `ART_SHIP_MANIFEST.json`. The generator refuses any file whose register status isn't FROZEN or whose bytes, sha256 or dimensions disagree. |
| Integration map | `js/data/art_integration.js` (authored) | Which runtime environment id uses which frozen master, plus the presentation metadata Engineering authored from the pixels: floor/contact line, depth base, condition layers. ART SHIP 008 adds surface-scoped `conditions` (under actors) / `foreground` (over actors) layers, `baseEnv` compositions and layer-registered slots. |
| Surface table | `js/data/art_surfaces.js`, generated by `tools/art-integration.mjs` | Adventure node → the Art-mapped census screen it presents, so surface-scoped layers activate on exactly the mapped screens, even when a runtime-bound cast changes the live key. |
| Runtime registries | `js/data/btf/environments.js`, `js/data/btf/people.js` | Resolve frozen art by id through the registry. Anchors become the default sprite where no earlier approved sprite exists; `states` lists every approved alternate. Ids with no frozen art keep their RAPixel placeholder. |
| Content states | Adventure nodes: `{id, state}` | A node names an approved state (`rich@ramen_apron`); the adventure scene resolves it through `person.states`. The gate fails if content names a state that isn't frozen. |
| Combat states | `js/scenes/combat2.js` | Frozen enemy states follow the fight's own events (telegraph → strike when Rich is hurt → hit → defeated/poof on a win). They're passed to the Director as the state envelope, so the camera never jumps. |
| Asset metadata | `tools/presentation-assets.mjs`, `tools/presentation/annotations.json` | Every registry environment and actor gets Director metadata automatically. Face boxes for all 74 frozen character sprites were authored by inspecting the pixels; `noFace` marks poses with no readable face by design. |
| Matrix | `docs/art_integration/INTEGRATION_MATRIX.json`, generated by `tools/art-integration.mjs` | Per frozen file, runtime demand and screen status, derived from the live runtime plus the reviewer record `tools/art-integration/review.json`. |

### Environment staging (authored presentation metadata)

All 44 frozen environments (43 masters plus the ocean-floor base) were inspected internally with Rich at the approved ~1.85× on the candidate line. Every ART SHIP 005–007 master is authored to the Art contract: primary contact line y=372, depth base 1. The ocean floor uses Ship 004's recommended 370 with exact-origin ladder layers: intact for `ocean_floor`, collapsed for `ocean_floor_collapsed`, never both.

### Director change: metadata-driven slot staging

`adventureStage(env, cast, {assets})` now uses real sprite metadata. It is generic, with no per-screen positions:
1. Each slot is clamped so that actor's actual visible body stays inside the environment. This replaces the fixed "typical 30 px body" assumption.
2. When a focal group is too wide to reach the conversation consistency floor at 360/390/430, the spare space between neighbouring bodies (anything over 2 world px) closes proportionally around the group's centre. Overlapping pairs are never moved.

Screens that already reach the floor are untouched (11 of 102 screens move, all former exceptions or new state screens). Combat minions are observers, not speakers.

## Extending

- **New frozen Ship:** run `node tools/art-registry.mjs`, map new environment ids in `js/data/art_integration.js`, author faces, then `node tools/presentation-assets.mjs`.
- **After any art/runtime change:**
  - `node tools/presentation-adventure-dryrun.mjs [--combat]`
  - the sweeps
  - review
  - `--write-lock`
  - `node tools/art-integration.mjs`
- **Reviewer decisions** (HOLD, ambiguity, polish) go in `tools/art-integration/review.json`, never in the generated matrix.
- **Regression locks vs final art:** the Wave 1/2 locks are framing regression locks. Final-art acceptance is the matrix `PASS (final art)` status, and HOLD screens are not final presentation.
