# FIX-01 — CDB required fixes (ACCEPT WITH REQUIRED FIXES)

Base for this fix: `a041f8aa55ab1c5378ed1b05cecaf8e2df4991d3`.

## R1 — ambience retry loop (fixed)
`enterScene` no longer starts an open 120 ms retry timer. `startSceneAmbience(sceneId,ambienceId,token)` returns
immediately for unregistered/`file:null` entries (no timer, no attempt). For registered entries it performs a single
bounded `preload(...).then(...)` attempt tied to a monotonically increasing `sceneToken`; the start is skipped if the
token or current scene changed, and `stop()`/`releaseScene()` on scene exit invalidates the prior attempt. Added
diagnostics `ambienceAttempts`, `pendingAmbience`, `sceneToken`.

## R2 — audio settings control the current soundtrack (fixed)
`applyElementMix()` mirrors the MUSIC setting onto `#soundtrack.volume` and MUTE onto `#soundtrack.muted`; it runs on
load, on `DOMContentLoaded`, and whenever `setVolume`/`setMuted`/`toggleMuted` are called (it does not require an
AudioContext). The settings screen is unchanged and now functional.

## Directly-related safety fixes
- **Scene ID mapping:** `manifest.scenes` now keys real runtime scene IDs — `bedroom`, `battle` (throne room),
  `adventure`, `tripTravel`. Removed `throne`/`phone`/`castle` (not runtime scenes); resident UI/phone IDs are
  preloaded once on unlock instead.
- **Double-fire guard:** the global UI_TAP/UI_BACK listener moved to the bubble phase and skips a click flagged
  `event.__raSfxHandled`; the phone overlay marks its specific actions (`app:`, `settings`, `toggleMute`, `tokyo`)
  so they do not also fire generic UI_TAP.
- **Unlock listener cleanup:** the `pointerdown/touchstart/keydown` unlock listeners are removed after first unlock.
- **First-scene ambience:** on unlock, the engine re-enters the current scene, so a scene already active when the
  gesture arrives can start its ambience.
- **Preload before unlock:** `preload()` returns without creating an `AudioContext` until unlock; resident/scene
  preloads are deferred until then.
